# Data Model: Профиль учётной записи и авторизация класса C

Дата: 2026-11-19. Хранилище одно: PostgreSQL. Имена таблиц ниже — логические. Физические имена в миграции совпадают с ними. Связанные решения: [research.md](research.md). Контракт чтения: [contracts/account-api.yaml](contracts/account-api.yaml).

Правило BCNF для каждой таблицы: каждая нетривиальная функциональная зависимость имеет определителем суперключ. Факт, который выводится из другого, колонкой не хранится (FR-024).

Длина текста в ограничениях базы — `char_length` (кодовые точки), в том же смысле, что проверка в домене.

## Учётная запись — `account`

Именованный человек. Одна строка на ника.

| Поле | Ограничение |
| --- | --- |
| `account_id` | UUID, первичный ключ |
| `nick` | не пусто, `char_length` 1..64, без краевых пробелов, только английские буквы, цифры, пробел, апостроф, кавычка, точка с запятой и дефис, уникален `COLLATE "C"` |
| `display_name` | не пусто, `char_length` 1..128, без краевых пробелов, уникальность не нужна |
| `password_hash` | не пусто, строка Identity V3, не пароль |

Ключи-кандидаты: `account_id` и `nick`. Зависимости: `account_id → nick, display_name, password_hash` и `nick → account_id, display_name, password_hash`. Имя никого больше не определяет. BCNF выполняется.

Связи: ровно одна `board`, ноль или больше `access`, ноль или больше строк `account_audit_event`.

Проверка из требований: FR-001, FR-002, FR-003, FR-010, FR-012. При создании `display_name` равен уже обрезанному нику. Ник после вставки не меняется: триггер `BEFORE UPDATE` отвергает смену `nick`. Имя и хэш меняются на месте, история не пишется. Удаление строки триггер отвергает: удаления учётки в спецификации нет.

Пароль в таблицу не входит.

## Доска — `board`

Доска одной учётки. Имени доски нет: в контракте `/v1` его нет, а копия ника здесь была бы вторым фактом.

| Поле | Ограничение |
| --- | --- |
| `board_id` | UUID, первичный ключ |
| `account_id` | не пусто, уникален, внешний ключ на `account`, `ON DELETE RESTRICT` |

Ключи-кандидаты: `board_id` и `account_id`. Зависимости взаимно однозначные. BCNF выполняется.

Создаётся в той же транзакции, что и учётка, вместе с тремя колонками.

## Колонка — `column`

| Поле | Ограничение |
| --- | --- |
| `column_id` | UUID, первичный ключ |
| `board_id` | не пусто, внешний ключ на `board`, `ON DELETE RESTRICT` |
| `name` | не пусто, хранится буквально |
| `position` | `smallint`, уникальна в пределах `board_id` |

Уникальность имени в доске: индекс `(board_id, lower(name))` плюс проверка домена `OrdinalIgnoreCase` до вставки. Точное повторение закрывает уникальность `(board_id, name)`.

Ключ: `column_id`. Также ключи `(board_id, lower(name))` и `(board_id, position)`, раз ограничения их удерживают. Иные зависимости не объявляются. BCNF выполняется.

Начальные строки новой доски, позиции 0, 1, 2, имена точно `ToDo`, `InProgress`, `Done`. Добавления и переименования колонки этой фичей нет. Удаление колонки разрешено. Удаление доски триггером не требуется отдельно: доску не удаляет ни один сценарий, внешний ключ с учётки ограничивает удаление учётки.

Порядок колонок в ответе — по `position`.

## Карточка — `card`

| Поле | Ограничение |
| --- | --- |
| `card_id` | UUID, первичный ключ, задаёт сервер |
| `column_id` | не пусто, внешний ключ на `column`, `ON DELETE CASCADE` |
| `title` | не пусто, буквально, без обрезки |
| `description` | пустое значение допустимо как NULL; пустая строка, если её передали, хранится как пустая строка |
| `deadline` | `date` или NULL, без времени суток |
| `created_at` | `timestamptz`, UTC, не NULL, дробная часть секунды нулевая |

`board_id` на карточке нет: его определяет `column_id`. Имени владельца и ника на карточке нет.

Ключ: `card_id`. Зависимость от ключа ко всем полям. BCNF выполняется. Идентификатор глобально уникален первичным ключом и не переиспользуется.

Правки карточки этой фичей нет. Удаление физическое.

## Метка — `card_tag`

| Поле | Ограничение |
| --- | --- |
| `card_id` | внешний ключ на `card`, `ON DELETE CASCADE` |
| `tag` | не пусто, буквально |

Первичный ключ `(card_id, tag)`. Дополнительно уникальность `(card_id, lower(tag))`. Домен отвергает пару, равную без учёта регистра (`OrdinalIgnoreCase`), до вставки, целиком, без частичного сохранения карточки. Отдельной таблицы-справочника тегов нет: метка одной карточки не правит метку другой.

Неключевых атрибутов нет. BCNF выполняется.

## Доступ — `access`

Один успешный вход — одна строка. Несколько строк одной учётки разрешены.

| Поле | Ограничение |
| --- | --- |
| `access_id` | UUID, первичный ключ, он же `jti` токена |
| `account_id` | не пусто, внешний ключ на `account`, не уникален |
| `issued_at` | `timestamptz`, UTC, целая секунда |
| `ended_at` | `timestamptz` или NULL |

`expires_at` нет. Конец срока — `issued_at + interval '12 hours'`. Источник в этой таблице не хранится: он пишется один раз в журнал входа.

Ключ: `access_id`. Зависимости только от него. `ended_at` не выводится из `issued_at`. BCNF выполняется.

### Переходы

- Успешный вход создаёт строку: `ended_at` пусто. Это живой доступ, если ещё не наступил `issued_at + 12 часов`.
- Человек завершает этот доступ: выставляется `ended_at`. Другие строки той же учётки не меняются.
- Смена пароля и смена имени строки `access` не меняют.
- Новый вход добавляет новую строку и не заполняет `ended_at` у старых.
- Когда `now >= issued_at + 12 часов`, доступ мёртв без записи в строку. Отдельного состояния «истёк» в таблице нет.
- Мёртвый доступ снова живым не становится.

Оба исхода для вызывающей стороны — один код `no_active_access`: завершённый, истёкший, отсутствующий и с неверной подписью.

## Журнал владельца — `account_audit_event`

События ника, у которого уже есть учётка. Ник колонкой не хранится.

| Поле | Ограничение |
| --- | --- |
| `event_id` | UUID, первичный ключ |
| `account_id` | не пусто, внешний ключ на `account`, `ON DELETE RESTRICT` |
| `occurred_at` | `timestamptz`, UTC, целая секунда |
| `event_type` | одно из: `sign_in`, `access_end`, `password_change`, `display_name_change`, `foreign_access_denied`, `column_deleted`, `card_deleted` |
| `outcome` | `success` или `failure` |
| `source` | NULL или строка 1..45. Обязателен тогда и только тогда, когда `event_type = sign_in` |
| `object_name` | NULL или текст. Обязателен тогда и только тогда, когда тип — `column_deleted` или `card_deleted` |

Ключ: `event_id`. Ник, имя и пароль из учётки сюда не копируются, иначе `account_id → nick` имел бы определителем не ключ события. BCNF выполняется.

Чтение для владельца подставляет ник соединением. Это тот же неизменяемый ник, не второй редактируемый факт.

Вставка только. Триггер отвергает UPDATE и DELETE для любой роли.

Неудачный вход в существующий ник — строка с `sign_in` / `failure` и источником. Успешный вход — `sign_in` / `success` и источник. Завершение — `access_end` / `success`, источник пуст. Смена пароля и имени — успех или `failure` без старого и нового значения. Отказ в чужих данных — `foreign_access_denied` / `failure` на учётке того, кому отказали, `object_name` пуст. Удаление — успех и имя удалённого объекта (имя колонки или заголовок карточки).

## Журнал без владельца — `unowned_audit_event`

Только неудачный вход в ник длиной 1..64, которого нет. К учётке не прикрепляется, даже если такой ник создадут позже.

| Поле | Ограничение |
| --- | --- |
| `event_id` | UUID, первичный ключ |
| `attempted_nick` | не пусто, `char_length` 1..64, буквально |
| `occurred_at` | `timestamptz`, UTC, целая секунда |
| `event_type` | только `sign_in` |
| `outcome` | только `failure` |
| `source` | не пусто, 1..45 |

`account_id` нет. Ключ — `event_id`. BCNF выполняется: попытка ника не определяет учётку.

Роль `kanban_app` делает только INSERT. SELECT есть у `kanban_operator`. Триггер отвергает UPDATE и DELETE.

Пустой ник и ник длиннее 64 сюда не пишутся (решение 11 в research). Пароль не пишется.

## Что сознательно не является таблицей

- Группа, выдача доступа, приглашение.
- История пароля, история имени, мягко удалённая карточка.
- Вторая копия доски в JSON или SQLite.
- Сессия ASP.NET и refresh-токен.
- Поля старого профиля: фамилия, почта, дата рождения, фотография.

## Проверки до записи

Домен отвергает значение до открытия транзакции записи, если исход уже ясен без базы:

- создание: ник (пустота, длина, набор символов — иначе `nick_invalid`), затем пароль;
- смена имени: обрезка и длина;
- смена пароля: длина нового пароля до сверки текущего;
- карточка: заголовок, срок, повтор метки;
- вход: форма тела; пустой, слишком длинный или с символом вне набора ник не становится `nick_invalid`. Символ вне набора не открывает доступ.

Уникальность ника и гонка двух вставок решаются индексом, не предварительным чтением. Ответ второй транзакции — `nick_taken`.
