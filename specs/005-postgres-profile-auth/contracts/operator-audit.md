# Контракт: журнал оператора

Интерфейс для оператора, не для учётки и не для фронтенда. HTTP-метода у этого журнала нет. Модель строк — [data-model.md](../data-model.md), таблица `unowned_audit_event`. Коды отказов API — [account-api.yaml](account-api.yaml).

## Кто читает

Роль PostgreSQL `kanban_operator`. Пароль роли приходит из окружения `OPERATOR_DB_PASSWORD` при первой инициализации контейнера. В репозитории пароля нет.

Роль приложения `kanban_app` вставляет строку, когда вход не нашёл ник длиной 1..64, и не имеет права `SELECT` на эту таблицу. Обычный токен учётки эти строки не получает. Позже созданная учётка с тем же ником старые строки не забирает: колонки учётки в таблице нет.

`UPDATE` и `DELETE` отвергает триггер. Действия профиля и доски до этой таблицы не доходят.

## Что видно в строке

Время UTC до секунды, ник попытки, тип `sign_in`, результат `failure`, источник обращения. Пароля нет. Имени, доски и хэша нет.

Источник — тот же признак, что у журнала владельца: адрес узла без порта. Одинаковый адрес даёт одинаковую строку.

## Чтение

Подключение строкой `KANBAN_OPERATOR_CONNECTION` (роль `kanban_operator`, база `kanban_account`):

```sql
SELECT occurred_at, attempted_nick, event_type, outcome, source
FROM unowned_audit_event
ORDER BY occurred_at, event_id;
```

Ожидание: видны только неудачные входы в ник, которого не было. Успешные входы и неудачи уже существующего ника здесь отсутствуют — они в журнале владельца и читаются через `GET /v1/accounts/{nick}/journal`.
